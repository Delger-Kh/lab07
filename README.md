## Дүгнэлт (debrief)

| Согог | Аялал | Түвшин |
|---|---|---|
| BUG-01 Хоосон Гарчиг/Зохиолч хүлээн авна | Couch Potato | UI + API |
| BUG-02 1000-2100-аас гадуур он хүлээн авна | Saboteur | UI + API |
| BUG-03 Он 1,999 гэж таслалтай харагдана | Supermodel | UI |
| BUG-04 «Устгах» товч ногоон | Supermodel | UI |
| BUG-06 Давхардсан ном нэмэгдэнэ | FedEx | UI + API |
| BUG-07 Буруу JSON → 200 OK (400 биш) | Saboteur | API |
| BUG-08 «Хуучин хувилбар» → /old Internal Server Error | Supermodel | UI/сервер |

Хамгийн үр дүнтэй нь Saboteur аялал байсан: curl-ээр буруу JSON, хоосон талбар, хязгаараас гадуур он, давхардсан ном илгээхэд API бүгдийг нь 200/201-ээр хүлээн авсан нь сервер тал огт validation хийдэггүйг нэг дор харуулсан. Supermodel аялал гурван согог (он таслалтай харагдах, Устгах товч ногоон, /old хуудас 500) олсон тул UI-ийн хувьд хамгийн олон согог өгсөн. Couch Potato аялал хоосон оролтын согогийг, FedEx аялал давхардсан номын согогийг илрүүлсэн. Charter-аас гадуур санамсаргүй олдсон зүйл бол хүчингүй он нь «Хамгийн шинэ он» тооцоог ч гажуудуулж 2101 гэж харуулсан явдал юм. Шалгагдаагүй үлдсэн нь хайлтын том/жижиг үсэг ба зохиолчоор хайх, «Нийт ном» тоолуур ба мөрийн тооны зөрүү (BUG-05 гэж сэжиглэсэн ч баталгаажаагүй), маш урт оролтод хүснэгт эвдрэх эсэх, мессежийн үсгийн алдаа — эдгээр нь дараагийн session-ий charter болно. Лаб 1-ийн Playwright автомат тест BUG-01, BUG-02, BUG-06-г (мөрийн тоо, мессежийг assert хийж), BUG-07-г (request API-аар статус кодыг шалгаж), BUG-08-г (/old хуудасны хариуны статусыг шалгаж) барих байсан. BUG-03 (он таслалтай) нь яг «1999» текстийг assert хийсэн тест бичсэн тохиолдолд л баригдах байсан, ихэнх тест үүнийг алгасна. BUG-04 (товчны өнгө) нь CSS-ийн өнгийг тусгайлан шалгах эсвэл visual regression snapshot ашиглаагүй бол зөвхөн хүний нүдээр олдох согог юм. Иймээс автомат тест нь функциональ дүрмийг найдвартай шалгадаг бол exploratory тест нь хэн ч assert бичихээр төлөвлөөгүй харагдах, ойлгомжийн согогийг олоход илүү үр дүнтэй.
